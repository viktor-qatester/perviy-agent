# Обновление расписания на VPS

Цель: одна автоматическая рассылка во вторник и пятницу утром, 05:00 Europe/Minsk.
GitHub Actions — единственный включённый автоматический отправитель. Команда
`/digest` остаётся доступной для ручного сбора.

## Применить к работающему боту

1. Найти сервис и его каталог. Если сервис называется `qa_bot.service`, проверить:

   ```bash
   systemctl show qa_bot.service -p WorkingDirectory -p ExecStart -p EnvironmentFiles
   ```

2. В подтверждённом каталоге проекта проверить `git status`, затем обновить код:

   ```bash
   git pull --ff-only origin main
   ```

   При локальных изменениях или ошибке pull остановиться и разрешить конфликт,
   не сбрасывать изменения. Команды выполняются в каталоге `perviy-agent`.

3. В `.env` изменить только следующие настройки, сохранив токены и остальные поля:

   ```dotenv
   SCHEDULE_ENABLED=false
   SCHEDULE_DAYS=tue,fri
   SCHEDULE_TIME=05:00
   TIMEZONE=Europe/Minsk
   ```

   Проверить те же переменные в `EnvironmentFile`/unit-файле или настройках
   контейнера, если они там заданы: переменные процесса имеют приоритет над `.env`.
   Не публиковать `.env` и не отправлять полный вывод окружения с токенами.

4. Перезапустить подтверждённый сервис:

   ```bash
   sudo systemctl restart qa_bot.service
   systemctl is-active qa_bot.service
   journalctl -u qa_bot.service --since "5 minutes ago" --no-pager
   ```

   Ожидаемый результат: сервис активен, в новом запуске есть
   `Schedule disabled (SCHEDULE_ENABLED=false)`.
   Если бот работает в Docker, использовать фактический compose-сервис и
   пересоздать контейнер с обновлённым кодом и окружением вместо systemctl.

5. Проверить, что Windows Task Scheduler, cron, systemd timers и другие экземпляры
   этого бота не выполняют дополнительный `src/main.py --send`.
   Отключать только подтверждённые дубли этого проекта.

## Проверить GitHub Actions

В `.github/workflows/daily-digest.yml` должно оставаться `0 2 * * 2,5`.
Это вторник/пятница 02:00 UTC, то есть 05:00 по Минску.
Ручной `workflow_dispatch` также отправляет дайджест — не использовать его
как проверку без намерения отправить сообщение.

GitHub Actions допускает задержки запуска. Если нужна доставка строго в 05:00,
следует отдельно перенести единственный автоматический запуск на VPS и отключить
schedule в GitHub Actions, а затем проверить этот VPS. Не включать оба механизма.
